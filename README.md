# نظام المحاسبة الزراعية (Agricultural Accounting System)

نظام محاسبي متكامل لإدارة المزارع مبني على Laravel 12، بواجهة عربية (RTL) تعتمد Bootstrap 5.

## الوحدات الأساسية

- **إدارة المحاصيل والأراضي**: تسجيل المحاصيل والأراضي مع المساحة (دونم) ونوع الحيازة.
- **المواسم الزراعية**: ربط كل موسم بمحصول وأرض، مع حالة (نشط / مغلق-مؤرشف).
- **سجل المصاريف**: بنود مصاريف حرة مع تعدد العملات (USD / TRY / SYP) وسعر الصرف.
- **سجل المبيعات**: أوزان بالطن والكيلوغرام، حساب الإجمالي تلقائياً، الواصل والمتبقي.
- **التقارير المالية**: أداء المحاصيل، كشف حساب التاجر، تحليل المصاريف حسب البند، تصدير Excel وطباعة.

## الميزات المضافة

### 1. النسخ الاحتياطي لقاعدة البيانات
- صفحة **الإعدادات والنسخ الاحتياطي** (`/settings`) وزر تنزيل نسخة `.sql` بضغطة واحدة (`/settings/backup/download`).
- الخدمة `App\Services\DatabaseBackupService` تستخدم أداة `mysqldump` إن كانت متاحة على الخادم،
  وإلا تولّد النسخة عبر PHP مباشرة (تدعم MySQL/MariaDB و SQLite) مع جمل `CREATE TABLE` وبيانات `INSERT`.

### 2. سندات القبض ودفعات التجار
- الجدول `buyer_payments` والنموذج `App\Models\BuyerPayment` (المبلغ، العملة، سعر الصرف، التاريخ، الملاحظات،
  رقم السند، ارتباط اختياري بفاتورة بيع وموسم).
- تسجيل دفعة من داخل **كشف حساب التاجر** أو من صفحة **سندات القبض** (`/buyer-payments`).
- تُخصم الدفعات تلقائياً من الرصيد المتبقي عبر `App\Services\BuyerAccountService`، وتنعكس على
  لوحة التحكم (الديون المستحقة)، وكشف الحساب، وتصدير Excel.
- طباعة سند القبض: `/buyer-payments/{id}/receipt`.

### 3. إغلاق وأرشفة المواسم
- إغلاق الموسم (`POST /seasons/{season}/close`) يجمّد مبيعاته ومصاريفه: يُمنع الإضافة والتعديل والحذف
  حتى إعادة الفتح (`POST /seasons/{season}/reopen`).
- **أرشيف المواسم** (`/seasons/archive`) لمقارنة الإنتاجية (طن، طن/دونم) والأرباح عبر السنوات،
  مع فلاتر للمحصول والسنة ومخطط بياني للمقارنة.

### 4. المخططات البيانية التفاعلية
- دمج Chart.js في لوحة التحكم: مخطط أعمدة لمقارنة إيرادات/مصاريف/صافي أرباح المحاصيل،
  ومخطط دائري (Doughnut) لتوزيع نسب المصاريف حسب البنود، إضافة إلى مخطط المقارنة السنوية في الأرشيف.

### 5. المصادقة وتسجيل الدخول
- شاشة تسجيل دخول (`/login`) تقبل البريد الإلكتروني أو اسم المستخدم، مع خيار "تذكّرني".
- جميع مسارات النظام محمية بـ `middleware('auth')`، وزر تسجيل الخروج في الشريط العلوي وصفحة الإعدادات.

### 6. تعدد المزارعين وعزل البيانات (Multi-Tenancy)
- عمود `user_id` في كل الجداول الأساسية: `crops`, `fields`, `expense_categories`, `seasons`,
  `expenses`, `sales`, `buyer_payments` (مع فهرس ومفتاح أجنبي على MySQL).
- حقل `role` في جدول `users` بقيمتين: `admin` (وصول كامل لبيانات كل المزارعين وإدارتهم)
  و `farmer` (يرى ويحرّر بياناته فقط).
- العزل يُطبَّق تلقائياً عبر `App\Models\Scopes\OwnedByUserScope` والسمة `App\Models\Concerns\BelongsToUser`:
  كل استعلام يُفلتر حسب المستخدم المسجّل، وكل سجل جديد يُختم باسم مالكه تلقائياً.
- الحماية تشمل الوصول المباشر بالمعرّف (Route Model Binding يعيد 404 لبيانات مزارع آخر)
  ومنع ربط مصروف أو فاتورة أو سند بموسم/فاتورة تعود لمزارع آخر.
- عند الترقية تُربط كل البيانات الموجودة مسبقاً بحساب مدير النظام تلقائياً داخل المهاجرة.
- تنزيل النسخة الاحتياطية الكاملة صار مقتصراً على مدير النظام (لأنها تشمل بيانات الجميع).

### 7. تسجيل الحسابات وإدارة المستخدمين
- صفحة `/register` لإنشاء حساب مزارع: الاسم الكامل، اسم مستخدم فريد، البريد الإلكتروني (Gmail)،
  رقم هاتف اختياري، وكلمة مرور (8 أحرف على الأقل مع تأكيدها).
- تسجيل الدخول يقبل اسم المستخدم أو البريد الإلكتروني، والحسابات الموقوفة (`is_active = false`) تُمنع من الدخول.
- استعادة كلمة المرور عبر البريد: `/forgot-password` ثم `/reset-password/{token}`
  برسالة عربية مخصصة (صلاحية الرابط 60 دقيقة). لتفعيل الإرسال عبر Gmail اضبط `MAIL_MAILER=smtp`
  و `MAIL_HOST=smtp.gmail.com` و `MAIL_PORT=587` مع "كلمة مرور التطبيقات" من حساب Google.
- لوحة مدير النظام `/admin/users`: عرض كل الحسابات مع إحصائيات بياناتها، بحث وفلترة حسب الصلاحية،
  إنشاء حساب، تعديل بياناته وصلاحيته، إيقاف/تفعيل، عرض ملف المزارع ومواسمه، وحذف الحساب مع بياناته.
  (لا يستطيع المدير سحب صلاحيته أو إيقاف/حذف حسابه بنفسه.)

### 8. نوع الموسم والفلترة حسبه
- حقل `type` في جدول `seasons` بقيم: `winter` شتوي، `summer` صيفي، `autumn` خريفي، `spring` ربيعي.
- قائمة اختيار النوع في نموذجي إنشاء وتعديل الموسم، وشارة النوع في جداول المواسم والمصاريف والمبيعات.
- فلترة إضافية حسب نوع الموسم في **سجل المصاريف** و**سجل المبيعات** بجانب فلترة الموسم المحدد
  (وفلترة التاجر في سجل المبيعات)، وكذلك في صفحتي المواسم والأرشيف.

### 9. البريد الإلكتروني الفعلي (Gmail SMTP) وقالب الرسالة
- `.env.example` يحتوي إعدادات Gmail القياسية (`smtp.gmail.com:587` مع `tls`) وخطوات إنشاء
  **كلمة مرور التطبيقات** من حساب Google. أثناء التطوير تبقى `MAIL_MAILER=log` لتُكتب الرسائل
  في `storage/logs`، وتُغيَّر إلى `smtp` عند التشغيل الفعلي.
- `App\Notifications\ResetPasswordNotification` يرسل رسالة استعادة كلمة المرور بقالب
  `resources/views/emails/reset-password.blade.php`: تصميم احترافي RTL بجداول متوافقة مع عملاء
  البريد، شعار النظام، زر إعادة التعيين، مدة صلاحية الرابط، ونسخة نصية من الرابط.
- الإرسال المباشر أو عبر الطابور يُضبط من `MAIL_QUEUE_NOTIFICATIONS`
  (عند تفعيله شغّل `php artisan queue:work`؛ وإلا تُرسل الرسالة مباشرة عبر اتصال `sync`).

### 10. إرفاق المستندات والصور
- عمود `receipt_image` في `expenses` (صورة فاتورة الشراء أو إيصال الصرف) وفي `buyer_payments`
  (صورة سند القبض أو الإشعار البنكي/الحوالة).
- الرفع مدعوم من نماذج المصاريف (إضافة/تعديل مع استبدال أو حذف المرفق) ومن نوافذ تسجيل الدفعات
  في صفحة سندات القبض وكشف حساب التاجر. الصيغ: JPG, PNG, WEBP, GIF, PDF بحد أقصى قابل للضبط
  (`ATTACHMENTS_MAX_SIZE_KB`، افتراضياً 4 ميغابايت).
- التخزين على قرص `public` ضمن `storage/app/public/receipts/{expenses,payments}` ويُربط بـ
  `php artisan storage:link`. حذف السجل يحذف ملفه تلقائياً (سمة `HasReceiptAttachment`).
- مصغّرات الصور تظهر في سجل المصاريف، سجل سندات القبض، كشف حساب التاجر، صفحة الموسم وسند الطباعة،
  مع نافذة تكبير وزر تحميل، وأيقونة خاصة لملفات PDF.

### 11. التنبيهات والإشعارات الذكية
- `App\Services\AlertService` يولّد التنبيهات تلقائياً ضمن نطاق بيانات المستخدم:
  * **ديون التجار المتأخرة**: تجاوز الدين لحد `ALERT_DEBT_THRESHOLD_USD`، أو مرور
    `ALERT_DEBT_IDLE_DAYS` يوماً دون أي دفعة.
  * **سقف المصاريف**: تجاوز مصاريف الموسم أو المحصول نسبة `ALERT_EXPENSE_RATIO` من الإيراد
    (تنبيه أحمر عند العمل بخسارة).
  * **مواسم بلا إيرادات**: موسم نشط صُرف عليه ولم تُسجَّل مبيعات خلال `ALERT_SEASON_IDLE_DAYS` يوماً.
- العرض: جرس تنبيهات مع عدّاد في الشريط العلوي (كل الصفحات)، قسم في لوحة التحكم،
  وصفحة `/alerts` مصنّفة حسب نوع التنبيه مع الحدود المعتمدة وروابط الإجراء المباشر.

## التنصيب

```bash
composer install
cp .env.example .env
php artisan key:generate

# للتشغيل السريع على SQLite
touch database/database.sqlite

php artisan migrate
php artisan db:seed          # ينشئ حساب المدير
php artisan storage:link     # لعرض صور الفواتير وسندات القبض
php artisan serve
```

بيانات دخول مدير النظام الافتراضية (قابلة للتعديل عبر `ADMIN_USERNAME` و `ADMIN_EMAIL` و `ADMIN_PASSWORD` في ملف `.env`):

| اسم المستخدم | البريد | كلمة المرور | الصلاحية |
| --- | --- | --- | --- |
| `admin` | `admin@agri.local` | `password` | مدير النظام |

يمكن للمزارعين إنشاء حساباتهم بأنفسهم من صفحة `/register`، أو ينشئها المدير من `/admin/users`.

### ترقية تثبيت قائم

```bash
git pull
php artisan migrate       # الأدوار وأسماء المستخدمين وأعمدة user_id ونوع الموسم وأعمدة المرفقات
php artisan storage:link  # مرة واحدة لعرض المرفقات
```

المهاجرة تربط كل البيانات الموجودة مسبقاً بأول حساب في النظام (مدير النظام)، فلا تُفقد أي بيانات.

> غيّر كلمة المرور الافتراضية قبل استخدام النظام في بيئة الإنتاج.
